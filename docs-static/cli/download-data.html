firna download-data#

Download Rfam data files and family alignments from the Rfam FTP site.

Synopsis#

firna download-data [--families SELECTOR ...] [--include NAME ...] [--scans-url URL] [options]

Description#

Downloads what --include names. Without --families the default is the shared Rfam files, core. With --families the default is core seed full, so each selected family’s seed alignment is extracted from Rfam.seed and its full alignment is downloaded into data/rfam/families/<family>/. Existing files are kept unless --overwrite is given, so an interrupted download can be completed by running the same command again. Files are transferred concurrently.

Choosing what to download#

Name

Downloads

Written to

core

The shared files Rfam.seed, Rfam.cm, Rfam.full_region and Rfam.pdb

data/rfam/

seed

Each selected family’s seed alignment, cut from Rfam.seed

data/rfam/families/<family>/<family>.seed.sto

full

Each selected family’s published full alignment

data/rfam/families/<family>/<family>.sto

fasta

Each selected family’s FASTA of seed and hit sequences

data/rfam/families/<family>/<family>.fa

scans

The finished scan tables of the Rfam seed sequences, RNA3DB and ArchiveII

data/scans/seeds-rfam.tbl, rna3db.tbl, archiveii.tbl

seed-fasta

Every Rfam seed sequence, or those of --families, in one FASTA file named family|name, made from Rfam.seed

data/scans/seeds.fa

The scans take hours to make, so scans replaces running firna scan-sequences for these three sources. --scans-url gives where they are: a folder that holds the three files, or an address with {name} where the file name goes. Without it the published location is used, and until one is published scans needs --scans-url. A table that is already there is kept.

seed-fasta is what firna scan-sequences searches to find which families resemble each other. Each sequence is written without gaps and with T as U, as RFxxxxx|name, so a scan of the file can be traced back to the family of every sequence. Rfam.seed is downloaded if it is missing, and an existing file is kept unless --overwrite is given.

seed, full and fasta need --families. Rfam.seed is downloaded when seed is included even without core, because the seed alignments are cut from it.

Rfam does not publish a full alignment for every family. Families without one are not processed by later stages. To fetch only what exists for such a family, leave full out of --include, because asking for a full alignment that does not exist fails with a 404 error. The FASTA of a family without a full alignment is the source of its sequences.

Options#

Option

Default

Description

--families FAMILIES

accessions (RF00030 or 30), all, 30-3000, 30- (onward) or -30 (up to)

--include NAME

what to download, any of core, seed, full, fasta, scans (the finished scan tables) and seed-fasta (every Rfam seed sequence in one FASTA file, made from Rfam.seed) (default: core, or core seed full with –families)

--scans-url URL

where the finished scan tables are, for scans: a folder that holds them, or an address with {name} for the file name (default: the published location)

--rfam-version RFAM_VERSION

CURRENT

release (default: CURRENT)

--overwrite

replace existing files

--workers WORKERS

4

concurrent transfers (default: 4)

--data-dir DIR

data folder used for every default path (default: $FIRNA_DATA, else ./data); paths given as options always win

Input#

No local input. Requires network access to ftp.ebi.ac.uk.

Output#

data/rfam/
├── Rfam.seed
├── Rfam.cm
├── Rfam.full_region
└── Rfam.pdb
data/rfam/families/<family>/
├── <family>.seed.sto    seed alignment
├── <family>.sto         full alignment, with full
└── <family>.fa          seed and hit sequences, with fasta

Examples#

firna download-data
firna download-data --families RF00005
firna download-data --families all
firna download-data --families 30-3000 --include seed full
firna download-data --families RF00005 --rfam-version 15.0
firna download-data --families RF00177 RF01960 --include seed fasta
firna download-data --include core scans
firna download-data --include scans --scans-url 'https://example.org/files/{name}?download=1'
