firna benchmark compare#

Show every structure for each hit of chosen families, laid onto its whole chain, with scores.

Synopsis#

firna benchmark compare [--families SELECTOR ... | --families-file TABLE.csv | --hits HITS.txt] [options]

Description#

This internal command is for inspecting hits by eye, such as the families where a library structure scores better than Rfam’s. It reads a finished firna benchmark evaluate-consensus run folder, the newest in data/evaluations/ or the one given with --evaluation-run, so nothing is aligned or scored again: the blocks match the run’s comparison tables exactly, take its settings, and are written in seconds. Every structure of the run is laid onto each chosen hit and shown with its score against the known structure:

Structure

Source

cm

The family CM’s own structure, which is also the structure of Rfam’s full alignment. It has no pseudoknots.

rfam_seed

Rfam’s seed SS_cons, with its pseudoknots

cacofold_<name>

Each CaCoFold fold in the structure library, with its main structure and extra layers merged into one structure. Where layers clash, the pair with the lowest E-value in the fold’s .cov file wins, and crossing pairs are written as pseudoknot letters.

Any other name

Each structure the run read from --structure-dir, under its own name, or each --fold method.

The selection options below narrow the run’s hits, and without any selection every evaluated family is used. The settings that decide which RNAs and hits were scored, and how, were given to make-set and evaluate-consensus, and are not given again here. Each result holds its RNA’s sequence, so a run made on another computer can be read anywhere.

The output is in Stockholm format, with one block per hit, as in the per-sequence annotation files used for RNase P. Every line is laid onto the hit’s whole chain, in the chain’s own orientation, so a minus-strand hit is shown reversed back onto the chain.

Choosing hits#

Hits are chosen by family, by individual hit, or both:

Option

Selects

--families

Families, with the usual selectors

--families-file PATH

Families from a table with a family column, such as a comparison table filtered in a notebook and saved as CSV, or from a plain list of accessions

--hits PATH

Hits from a file, as below

A hits file lists, for each family, the hits to compare. Each line holds a family accession followed by any number of hits, a family alone for all of its hits, or a hit alone for that hit in every chosen family. A hit is a chain, for all its hits (9cfn_A), or one hit (7jju_A/2-51). Text after # is ignored.

RF04326  7jju_A/2-51  9cfn_A
RF00437  9rw3_F/6-66
RF00001                 # every hit of this family

The file may instead be a CSV or tab-separated table with a hit column and, optionally, a family column; a row with a family and no hit selects all of that family’s hits. A family keeps only its listed hits when any hit is listed for it, and all its hits otherwise.

--only-improved then keeps only the families in which a library structure’s mean MCC over the family’s hits, counting straddling pairs as missed, is higher than that of --baseline, which is rfam_seed by default, by more than --min-gain, as in the comparison tables. All of an improved family’s hits are shown, including those where the library structure does worse, and a family is left out even if single hits improve when its mean does not.

Options#

Option

Default

Description

--families FAMILIES

accessions, all, ranges such as 30-3000, 30- or -30

--families-file FAMILIES_FILE

table with a family column, or one accession per line

--hits HITS

hits to compare: a table with family and hit columns, or lines such as RF04326 7jju_A/2-51, RF04326, or 7jju_A

--only-improved

keep only families where a library structure’s mean MCC over the family’s hits beats –baseline, with all their hits

--min-gain MIN_GAIN

0.0

with –only-improved, the margin in mean MCC a library structure must beat the baseline by (default: 0)

--baseline NAME

rfam_seed

with –only-improved, the structure to beat, by its name in the comparison tables (default: rfam_seed)

--evaluation-run RUN

the firna benchmark evaluate-consensus run folder whose hits, structures and scores are shown (default: the newest run in data/evaluations/)

--out OUT

write every hit to this one file (default: one file per family, <run>/<family>/<family>_eval_structures.sto in the evaluation run)

--list-families

print the selected families and exit

--data-dir DIR

data folder used for every default path (default: $FIRNA_DATA, else ./data); paths given as options always win

Output#

Without --out, each family’s hits are written to <run>/<family>/<family>_eval_structures.sto in the evaluation run. The files written are then listed in eval_structures_files.txt, in the run folder, with paths relative to that folder, so they can be copied from another computer with rsync --files-from:

rsync -avP --files-from=eval_structures_files.txt user@host:/path/to/run/ data/evaluations/run/
``` With `--out`, every
hit goes to that one file.

Each family's hits are preceded by a summary block of their own, with the
ID `<family>_summary` and no sequence. It gives each
structure's mean MCC over the family's hits shown, counting straddling pairs
as missed (`penal.`) and ignoring them, its difference from `rfam_seed`, and
the structure with the highest mean. A file written with `--out` begins with
an overview block, with the ID `overview`, holding a table with one row per
family that gives every structure's mean MCC and the best structure, so the
families can be compared at a glance:

STOCKHOLM 1.0#

#=GF ID overview #=GF CC OVERVIEW: mean MCC per family, straddling pairs penalised #=GF CC family hits cm rfam_seed cacofold_full cacofold_seed cacofold_seed_full best #=GF CC RF00437 6 0.659 0.659 0.906 0.891 0.928 cacofold_seed_full #=GF CC RF04326 4 0.330 0.470 0.735 0.754 0.754 cacofold_seed, cacofold_seed_full //

STOCKHOLM 1.0#

#=GF ID RF00437_summary #=GF CC FAMILY SUMMARY RF00437: mean MCC over 6 hits #=GF CC structure penal. ignored vs rfam_seed #=GF CC cm 0.659 0.659 +0.000 #=GF CC rfam_seed 0.659 0.659 +0.000 #=GF CC cacofold_full 0.906 0.906 +0.247 #=GF CC cacofold_seed 0.891 0.891 +0.232 #=GF CC cacofold_seed_full 0.928 0.928 +0.269 #=GF CC best by mean MCC: cacofold_seed_full (0.928) //


The summary and overview blocks hold only `#=GF` lines, with no sequence.
Programs that expect every Stockholm block to contain sequences may need to
skip them.

| Line | Content |
|---|---|
| `#=GF ID` | The chain and the hit's coordinates |
| `#=GF CC hit` | Coordinates, strand, bit score, E-value and scoring window |
| `#=GF CC` MCC table | One row per structure: its MCC on this hit, counting known pairs that straddle the hit as missed (`penal.`) and ignoring them. The family's means are in its summary block. See [Straddling pairs](evaluate.md#straddling-pairs). |
| `#=GC hit_region` | `*` over the bases of the hit |
| `#=GC SS_cons_known_<layer>` | The known structure of the whole chain |
| `#=GC SS_cons_<structure>` | Each structure, laid onto the chain. Bases outside the hit are unpaired. |
| `#=GF CC best` | The structure with the highest MCC, counting straddling pairs as missed, and any that tie with it |

The scores use the union of each CaCoFold fold's layers, as in
`firna benchmark evaluate-consensus`; the merged line shown can leave out a pair where two
layers clash.

## Examples

```bash
firna benchmark compare --families RF04326
firna benchmark compare --families 437 1734 4326
firna benchmark compare --families-file improved.csv --out improved.sto
firna benchmark compare --hits chosen_hits.txt --out chosen.sto
firna benchmark compare --families-file improved.csv --only-improved --min-gain 0.05 --out improved_hits.sto
firna benchmark compare --evaluation-run data/evaluations/<run> --only-improved --min-gain 0.05 --out improved_hits.sto
