firna benchmark evaluate-consensus#

Score consensus secondary structures, transferred onto each hit, against known structures.

Synopsis#

firna benchmark evaluate-consensus --families SELECTOR ... --hits-table TABLE [options]

Description#

Each reference RNA has a known structure: the RNA3DB annotations, or any table of names, sequences and structures, such as ArchiveII’s. Which references are used, and the part of each that is scored, were chosen by firna benchmark make-set, whose benchmark set (data/benchmark_set.tsv, or the file given with --benchmark-set) this command reads. The set records the reference structures and the subset, so they are not given again here. The hits table, from firna scan-sequences of the same sequences, assigns each RNA to an Rfam family and gives the location of the hit; only significant hits (inclusion flag !) are used. For each selected family:

  1. The hit sequences are aligned to the family model with cmalign.

  2. Each structure below is transferred onto every hit through that alignment.

  3. Each prediction is compared with the known base pairs, giving F1 and MCC.

Each consensus structure in your own folder of Stockholm alignments, from any folding method

None

rfam_seed is the structure Rfam publishes, so it is the baseline to compare other structures with. It is Rfam’s own annotation of its seed alignment, and cacofold_seed is a different structure, CaCoFold’s fold of that same seed alignment. cm shows what the family loses through the CM, and a comparison with cm favours any structure with pseudoknots wherever the known structure has them.

The default library holds CaCoFold’s structures, which are labelled cacofold_<name>. To score the consensus structures of another method, give its folder with --structure-dir. The labels are then the names in that folder, without a prefix.

Single-sequence folding#

With --fold rnafold, each hit’s sequence is also folded on its own with RNAfold and scored like the other structures, as a baseline that uses no alignment. RNAfold folds exactly the sequence the other structures are transferred onto: the hit, in the model’s orientation. Its columns in the comparison tables are rnafold_mean_f1 and rnafold_mean_mcc, and the run’s name ends in _rnafold. RNAfold never makes a family count as improved, which compares only library structures with the baseline.

Folding needs the RNAfold command, which the rfam environment installs from the viennarna package. A family skipped for lacking library structures is not folded either.

Folding methods are listed in FOLDERS in src/firna/tools/folding.py. Each entry is a command that reads FASTA on standard input and writes its predictions to standard output, and a reader for that output. To add another program, add an entry; most programs write the dot-bracket output that read_dotbracket reads, such as:

'linearfold': Folder(('linearfold',), read_dotbracket, 'install LinearFold'),

The new method is then available as --fold linearfold, and --fold rnafold linearfold scores both.

Best family only#

A region of a chain is often hit by several families: related families from one clan, such as the bacterial, archaeal and eukaryotic rRNAs, or unrelated ones that weakly match the same sequence. By default every significant hit is evaluated, so a chain can be scored against a family it does not belong to. With --best-family-only, hits on the same chain that overlap by more than half of the shorter one compete, and only the hit with the lowest E-value is kept. Hits with the same E-value are told apart by the higher bit score and then by the lowest family accession. A minus-strand hit competes like any other, so it is dropped whenever another family matches the region better. The number of hits dropped is printed at the start of the run, and run.json and report.json record the setting.

Straddling pairs#

A known pair straddles the scored region when one base lies inside it and the other outside, such as a pseudoknot whose partner lies beyond the end of a partial hit. No prediction can contain such a pair, because every structure is transferred onto the hit only. Every hit is scored in two ways:

Table

Straddling pairs

Measures

comparison_<settings>_straddling_penalised.csv

Kept in the known structure and counted as false negatives for every structure

How much of the RNA’s structure, where it touches the family, each structure recovers. A hit covering only part of a structure is penalised.

comparison_<settings>_straddling_ignored.csv

Removed from the known structure too

How well each structure matches where the family applies

Only false negatives differ between the two, so only sensitivity, F1 and MCC change; PPV is the same in both. Each straddling pair is also added to the possible pairs from which true negatives are counted, so the true negative count is the same in both. Each result lists the straddling pairs under known_annotation.straddling_pairs_1_based, and holds both scores per structure, under score and score_ignoring_straddling.

Known structure#

The known pairs come from one structure layer of each reference RNA, chosen with --reference-layer: secondary (default), or, for RNA3DB chains, any RNAview layer, such as cWW for cis Watson–Crick pairs only. A table has only secondary. Each result records the layer under known_annotation.reference_layer.

--resume re-evaluates every family of the run not yet marked evaluated. A run records its inputs in run.json; resuming with a different hits table, reference structures, subset, structure folder, structure selection, seed file, reference layer, best-family setting or folding methods is refused.

Run directories#

Command

Run directory

without --out

A new directory in data/evaluations/, named after the start time and the settings, such as 2026-10-06_14-32-05_rna3db_secondary or 2026-10-06_14-32-05_archiveii-RNaseP_secondary_best-family

--out PATH

PATH. The command stops if PATH already exists.

--out PATH --resume

Continues the run in PATH

--resume without --out

Continues the most recently started run in data/evaluations/

The most recent run is determined from the modification time of each run’s run.json, which is written once when the run starts; directory names are not used.

Runs from earlier versions#

A run made before the current format is rewritten with the script below, which counts the changes unless --apply is given. Results that hold no sequence read it from --annotations.

python scripts/migrate-evaluation-runs.py data/evaluations/RUN --annotations data/annotations --apply

Benchmark set#

Only the reference RNAs in the benchmark set are evaluated, and each is scored within its scoring window, which leaves out bases missing from an RNA3DB chain’s ends. Prediction is unchanged: the whole hit is aligned and every structure is transferred onto it. Scoring then ignores every pair with a base outside the window, and positions outside the window do not count towards the length used for MCC, so missing bases neither count for nor against a prediction. A hit that lies wholly outside its RNA’s window is not evaluated. Each result records its window under scoring_window.

Minimum coverage#

A hit that covers only part of a chain cannot be scored fairly: the known pairs outside it are straddling or missed. With --min-coverage, such as 0.95, a hit is evaluated only if it covers at least that fraction of its scoring window. Coverage is measured after --best-family-only and the benchmark set are applied, and the number of hits dropped is printed.

Structures

Comparison tables#

Each table’s name starts with the run’s settings: the reference source, the reference layer, then best-family with --best-family-only, then coverage95 with --min-coverage 0.95, then each folding method, such as rnafold. An RNA3DB run scored against cWW with --best-family-only writes comparison_rna3db_cWW_best-family_straddling_penalised.csv and comparison_rna3db_cWW_best-family_straddling_ignored.csv, so a table copied out of its run folder still says how it was made.

Both tables have the same layout: one row per family, with the mean F1 and MCC of each structure over that family’s hits. They differ only in how straddling pairs are scored; see Straddling pairs. Rfam’s structures keep their names, cm and rfam_seed, and come first, then the library structures, then any folding methods, such as rnafold. Each CaCoFold structure is prefixed with cacofold_, as in cacofold_seed, cacofold_full and cacofold_seed_full, so rfam_seed (Rfam’s annotation of its seed alignment) and cacofold_seed (CaCoFold’s fold of that alignment) cannot be confused. Structures from --structure-dir keep their own names.

family,status,hits,cm_mean_f1,cm_mean_mcc,rfam_seed_mean_f1,rfam_seed_mean_mcc,cacofold_full_mean_f1,...
RF01734,evaluated,5,0.72,0.75,0.94,0.94,0.78,...
RF00009,skipped_no_structures,12,,,,,,...

report.json#

Contains the reference source and subset, every family’s status and score summary, the number of reference RNAs with significant hits, the number of significant hits, and the hits whose query name matches no reference RNA (table_queries_not_selected).

Examples#

TABLE=data/scans/rna3db.tbl
firna benchmark make-set
firna benchmark evaluate-consensus --families RF00005 --hits-table $TABLE
firna benchmark evaluate-consensus --families all --hits-table $TABLE --workers 8
firna benchmark evaluate-consensus --families all --hits-table $TABLE --include-structures seed full seed_full
firna benchmark evaluate-consensus --families all --hits-table $TABLE --workers 8 --resume
firna benchmark evaluate-consensus --families all --hits-table $TABLE --out results/eval_v1
firna benchmark evaluate-consensus --families all --hits-table $TABLE --out results/eval_v1 --resume
firna benchmark evaluate-consensus --families all --hits-table $TABLE --list-families
firna benchmark evaluate-consensus --families all --hits-table $TABLE --reference-layer cWW --workers 8
firna benchmark evaluate-consensus --families all --hits-table $TABLE --best-family-only --fold rnafold --workers 8
firna benchmark evaluate-consensus --families all --hits-table $TABLE --benchmark-set data/benchmark_set_strict.tsv --best-family-only --min-coverage 0.95 --fold rnafold --workers 8

ArchiveII, with its own set made from its parquet file:

firna benchmark make-set --reference-structures data/archiveii/archiveii.parquet --subset RNaseP --out data/benchmark_set_rnasep.tsv
firna benchmark evaluate-consensus --families all --hits-table data/scans/archiveii-RNaseP.tbl --benchmark-set data/benchmark_set_rnasep.tsv --best-family-only

The consensus structures of another method, read from its own folder:

firna benchmark evaluate-consensus --families all --hits-table $TABLE --structure-dir data/my_method --best-family-only

To read a finished run from Python, use ConsensusEvaluation:

from firna.api import ConsensusEvaluation

run = ConsensusEvaluation.read('data/evaluations/my_run')
run['RF00010']                                      # the HitResults of one family
run.improved_families(min_gain=0.05, baseline='rfam_seed')
