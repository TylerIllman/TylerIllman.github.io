firna structures extract#

Extract each sequence’s secondary structure from the consensus structure of its MSA.

Synopsis#

firna structures extract --families SELECTOR ... [--msa PATTERN] [options]
firna structures extract --families SELECTOR ... [--msa PATTERN] [options]
firna structures extract --msa PATH [options]

Description#

For each sequence in an MSA, the alignment’s SS_cons is projected onto that sequence: gap columns are removed, and any base whose partner falls in a gap is left unpaired. The result is the sequence’s structure in WUSS notation, one character per nucleotide. Pseudoknots written as letters within SS_cons, as in Rfam’s alignments, are kept.

Extra structure layers#

CaCoFold writes its structure as a main nested structure on the SS_cons line plus extra layers on separate lines, such as SS_cons_pk_1 (pseudoknots), SS_cons_tr_1 (triplets) or SS_cons_sc_1 (side covariations). This is an R-scape extension to the Stockholm format, not found in Rfam’s own alignments.

By default only SS_cons is used. Extra layers are ignored, and the log reports how many each MSA had.

With --merge-layers, SS_cons and all extra layers are merged into one structure before projection:

  1. Every pair from SS_cons and from each extra layer is a candidate.

  2. Candidates are ranked by significance. Pairs that R-scape found to covary come first, lowest E-value first; E-values are read from the .cov file R-scape writes beside the fold, such as full_1.cacofold.cov for full_1.cacofold.sto. Pairs without an E-value follow in layer order, so pairs in SS_cons come before pairs in later layers.

  3. Pairs are added in that order. A pair is skipped if either of its bases is already paired, so every base has at most one partner.

Every pair that does not clash with another is therefore kept, and where pairs share a base, the most significant one wins. Without a .cov file, SS_cons wins clashes, followed by each layer in file order. Pairs that cross are written as WUSS pseudoknot letters (Aa, Bb, …). The log reports each merge:

[1/3] Ready: .../full_1.cacofold.sto: 9329 sequences -> full_1.cacofold.structures.tsv (merged 4 extra layers; E-values from full_1.cacofold.cov)

MSAs without extra layers are unaffected by --merge-layers. The merge is implemented in firna.structures.layers.

Selecting MSAs#

--msa is a path pattern. {family} stands for an Rfam accession, and * matches any part of a file or directory name.

  • With {family}, families are chosen with a positional accession or --families. all selects every family whose pattern matches a file.

  • Without {family}, the pattern is a plain file, directory or glob. A directory stands for every .cacofold.sto file in it, or every .sto file if it contains none.

Pattern

Reads, for RF00005

default

every CaCoFold fold of the newest run, data/cacofold/<run>/RF00005/*/*.cacofold.sto

data/rfam/families/{family}/{family}.sto

Rfam’s full alignment

data/alignments/<run>/{family}/seed.sto

the seed MSA built by firna structures build-alignments

data/cacofold/<run>/{family}/seed_full/*.cacofold.sto

the CaCoFold fold of seed_full only

A {family} pattern requires --families. A pattern without {family} accepts neither.

Input#

Stockholm MSAs with an SS_cons line. A selected family whose pattern matches no file is reported in the log and skipped.

Output#

Each MSA’s result is written as a tab-separated table in the family’s folder of a run, replacing .sto with .structures.tsv. The run takes the name of the run folder in data/extractions/, which is the start time unless --out names another:

data/structures/<run>/RF01852/
└── RF01852.structures.tsv

A source of the dataset can name every table of a run with a pattern, such as 'data/structures/<run>/*/*.structures.tsv', so the tables need not be combined first.

Column

Description

name

Sequence name, as in the MSA

sequence

The sequence with gaps removed

structure

SS_cons, or the merged structure with --merge-layers, projected onto the sequence, in WUSS notation

 
name	sequence	structure
ATHI01000004.1/148102-148191	GGAAGCGUAUCGUCACCGGUG...	(((((((((,<<<<<<____>>>>>>...

The table can be loaded with pandas.read_csv(path, sep='\t'). Each table is written in full before it replaces any previous file, so an interrupted run never leaves a partial table.

Run folder#

Each run also has its own folder, which records what was selected and what happened to every MSA.

data/extractions/2026-10-28_14-32-05/
├── run.json        the run's inputs
├── statuses/       one small file per MSA, written when that MSA finishes
└── report.json     the outcome of every selected MSA, and the totals

run.json holds the --msa pattern and whether --merge-layers was given, which a resumed run must repeat, and the families, --combine, --zip, --stats and --workers values for reference.

report.json lists every selected MSA with a status:

Status

Meaning

extracted

Extracted in this session, with its sequences count and table name

already_extracted

Extracted by an earlier session of this run and skipped by --resume

failed

Raised an error, given in error; or has no recorded result because its worker was killed, for example by the out-of-memory killer or the time limit

no_msa

A selected family has no file matching the pattern

It also gives counts for each status, the total sequences extracted, stopped (the error, when a killed worker ended the batch) and, when --combine is used, the combined table’s path and row count, and, when --zip is used, the zip file’s path and table count. The report is rewritten at the end of every session, including one that stopped early.

Resuming#

A run that failed, was stopped or was killed can be continued with --resume, with --out naming the run folder or, without it, the latest run:

firna structures extract --families all --msa 'data/rfam/families/{family}/{family}.sto' --resume

Only MSAs without a completed status are extracted, so failed MSAs are tried again and finished ones are not repeated. A killed run writes no report until it is resumed. The resumed run must use the same --msa pattern and --merge-layers setting, and is refused otherwise, so two sets of results are never mixed. Without --resume, a new run extracts every MSA again and replaces the tables beside them.

Combined table#

With --combine PATH, the tables of every selected MSA, including those skipped by --resume, are streamed into one table after extraction. Each MSA’s own table is still written.

Column

Description

family

Rfam accession, from the {family} pattern or else from the RFxxxxx in the MSA’s path

msa

The MSA’s table name without .structures.tsv, such as RF00005 or seed_full_1.cacofold

name, sequence, structure

As in each MSA’s table

Rows are copied one at a time, so the combined table can be far larger than memory. It is written under a temporary name and renamed when complete. --stats summarises it; see Statistics.

Zip file#

With --zip PATH, the tables of every selected MSA, including those skipped by --resume, are also copied into one zip file, as <family>/<table name>, such as RF00005/RF00005.structures.tsv. The zip is written under a temporary name and renamed when complete. It can be named as a source for firna dataset make-config, for example --source pretrain:rfam=structures.zip, and be copied to another computer as one file.

Statistics#

With --stats FOLDER, every selected MSA’s sequences are summarised after extraction, overall and per family:

Statistic

Description

sequences

Sequences

unique_sequences

Distinct sequences, ignoring case and treating T as U

nucleotides

Total sequence length

base_pairs

Total base pairs, including pseudoknot pairs

base_pairs_per_nucleotide

base_pairs divided by nucleotides

pseudoknotted_sequences, pseudoknotted_fraction

Sequences with at least one pseudoknot pair

min_length, median_length, mean_length, max_length

Sequence lengths

 
FOLDER/
├── summary.tsv     one row per set: all sequences, and without flag-0 hits
└── families.tsv    one row per family

The overall figures are also printed beside the published bpRNA-1m figures (Danaee et al. 2018). That paper does not report nucleotide, base pair or length totals, so those cells are empty.

Rfam’s full alignments contain every hit in full_region.txt for the family: flag-1 hits, which belong to the family, and flag-0 hits, which score above the family’s threshold but were assigned to a related family in the same clan. A flag-0 sequence therefore also appears in that other family’s alignment; RF00002’s full alignment holds 16,501 flag-1 and 31,084 flag-0 sequences. When data/rfam/full_region.txt exists, every statistic is also given without the flag-0 hits.

The same statistics are available in a notebook, from a combined table or from individual tables:

from firna.io.structure_tables import read_combined
from firna.structures.stats import comparison, read_flag0_names, statistics

summary, families = statistics(read_combined('data/structures.tsv'),
                               read_flag0_names('data/rfam/full_region.txt'))
print(comparison(summary))

Examples#

firna structures extract --families all --workers 8
firna structures extract --families all --msa 'data/rfam/families/{family}/{family}.sto'
firna structures extract --families RF01852 --msa 'data/alignments/<run>/{family}/seed.sto'
firna structures extract --families all --msa 'data/cacofold/<run>/{family}/seed_full/*.cacofold.sto' --resume
firna structures extract --families all --merge-layers
firna structures extract --families all --msa 'data/rfam/families/{family}/{family}.sto' --combine data/structures.tsv --stats data/structures_stats
firna structures extract --msa data/cacofold/default/RF00009/seed_full

Quote patterns containing {family} or *, so the shell passes them unchanged.
