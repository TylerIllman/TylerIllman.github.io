Migrating from earlier versions#

This page lists what changed between versions of FIRNA and how to bring existing data and scripts up to date. Earlier names are not accepted any more, so complete these steps before using a data folder or a job script from an earlier version.

Data folders#

Three scripts rewrite existing files, so that nothing has to be computed again. Each one lists its changes without writing anything until it is told to, and each can be run again safely. Run them in this order, when no job is writing to the data folder.

Script

Applies to

Changes

scripts/migrate-data-layout.sh

A folder with data/families/<family>/

Moves files into the run folders, and renames test_set*.tsv to benchmark_set*.tsv.

scripts/migrate-data-settings.py

Any older folder

Renames profile.json to dataset-config.json, renames saved settings in the dataset configs and run records, and completes older manifests.

scripts/migrate-evaluation-runs.py

Runs in data/evaluations/

Renames their settings and statuses, and fills in the fields that older results left out.

 
scripts/migrate-data-layout.sh --dry-run data original
python scripts/migrate-data-settings.py data
python scripts/migrate-evaluation-runs.py data/evaluations/* --annotations data/annotations

Read what they report, and then run the same commands without --dry-run, and with --apply for the two Python scripts. migrate-data-settings.py keeps the E-value that a dataset was built with, so a finished dataset stays current. A result that holds no merged structure keeps showing the main layer of each fold. Its scores are not affected.

An assignment made before rows with no family were grouped by sequence still builds, but copies of one RNA can be in different splits. Make it again with firna dataset split-components --overwrite to keep them together.

After the package is updated, install it again, which removes the rfam2ss command:

python -m pip install -e ".[dev]"
