Concepts#

This page defines the terms used throughout the documentation.

Rfam#

Rfam is a database of RNA families. A family is a group of homologous RNAs, identified by an accession such as RF00005 (transfer RNA). Each family has a covariance model (CM), a probabilistic description of the family’s sequence and secondary structure that is searched against sequences with the Infernal programs.

A seed alignment is a curated multiple sequence alignment (MSA) of representative sequences of a family. It carries a consensus structure (SS_cons), the secondary structure shared by the family, written in WUSS notation. A full alignment is the alignment of every sequence that scores at or above the family’s gathering threshold when the CM is searched against sequence databases.

The gathering threshold (GA) is a bit score assigned to each family by the Rfam curators. A sequence that scores at least this value against the family’s CM belongs to the family. A hit is a region of a query sequence that matches a model, with a bit score and an E-value. A clan is a group of families that Rfam records as evolutionarily related.

WUSS notation writes a secondary structure as a string with one symbol per position. Paired positions are brackets such as < and > or ( and ), and unpaired positions are . or _. Pseudoknots use further bracket types and letters.

Structures#

A projected structure is the consensus structure of an alignment transferred onto each sequence in it: a base is paired in the projected structure if it occupies a paired column and its partner’s column is also occupied. firna structures extract writes projected structures.

CaCoFold is a method of the R-scape program that predicts a secondary structure for an alignment from the covariation of its columns, including pseudoknots. It can produce several structure layers for one alignment.

A reference structure is a sequence with a structure that is taken as known, such as an RNA3DB annotation from a three-dimensional structure or an entry of ArchiveII. firna benchmark evaluate-consensus scores predicted structures against reference structures with the F1 score and the Matthews correlation coefficient (MCC).

Family graph and splits#

A link from family A to family B records that seed sequences of A match the model of B. Each link keeps the number of sequences that match and their E-values. A component is a set of families that are joined by links that meet a threshold, or by belonging to the same clan. A family with no link is a component of its own. A row with no Rfam family, because no scan hit meets member_evalue, has no links to follow, so the rows with the same sequence form one component.

A split is one of the sets that a dataset is divided into. By default the splits are train, valid (validation) and test, and a dataset can name its own. Each component is assigned to one split, and all families of a component receive the same split. Leakage occurs when sequences that are related appear in different splits, so that a model is evaluated on sequences similar to those it was trained on. Assigning whole components prevents leakage between families that Rfam or the scan shows to be related.

A dataset stage is a named part of a dataset with its own sources and split ratios, usually pretrain and finetune. A dataset has one list of sources for each dataset stage, and every row of a source takes its split from its family’s component. The same component therefore has the same split in every dataset stage.

Steps and pipelines#

A step is one operation of the package, such as scan-sequences or split-components. Each step is a method of a pipeline class and a command of the same name. A step has options, reads files, and writes files.

A stage is a step that reads input files and writes exactly one output file. A stage writes its output under a temporary name and renames it when the step succeeds, and it saves a run record (<output>.run.json) that lists the inputs and options the output was made from. The stage contract describes how a stage uses the record. The word stage in this sense is unrelated to a dataset stage.

A pipeline class holds the steps that complete one job. FIRNA has three: StructureBuilder obtains structures from Rfam, DatasetBuilder builds the family-informed dataset, and ConsensusBenchmark scores consensus structures. The steps are called one after another, and a stage whose output is current does no work. Pipeline classes gives the order of each.

Runs#

A run is one folder of results from a command that works through many families. Each time one of these commands starts it writes a new folder, named after the start time unless a name is given, so that earlier results are kept. A later command reads the newest run unless it is told which one to read.

Command

Folder of its runs

firna structures build-alignments

data/alignments/

firna structures run-cacofold

data/cacofold/

firna structures extract

data/structures/

firna benchmark evaluate-consensus

data/evaluations/

The data folder#

The data folder is the directory that holds all files. Its subdirectories are fixed by the layout (see firna show-layout). Pipeline classes given the same data folder read and write the same files.
