Conventions#

This page states the rules that every step, keyword and file of FIRNA follows. The rules are checked by the tests in tests/test_pipelines.py (ConventionTests) and tests/test_interfaces.py.

Steps#

A step is a method of a pipeline class, marked with @step, which names its command. Its keywords are made with option(), which carries the help sentence and the command-line details, so the signature is the only definition of an option. The Python keyword, the command-line option and the documentation are all derived from it, as in Typer.

@step('dataset find-components', stage=True, next='split-components')
def find_components(
    self, *,
    links: Path | None = option(help='links table from firna dataset link-families'),
    no_clans: bool = option(default=False, help='do not join the families of an Rfam clan'),
    overwrite: bool | str = False,
    dry_run: bool = False,
) -> Path:
    """Join related families into components, which stay together in a split."""

Argument of @step

Description

cli

The command as typed after firna. Its last word is the name of the step, in lower case with hyphens, and the method’s name is that word with underscores.

stage

Whether the step writes one output through _stage. The command then has --overwrite and --dry-run.

next

The name of the step that usually follows. The message printed after a step names it.

exclusive

Groups of keywords that the command refuses together.

A step raises exceptions and never exits the process. A step’s description is its docstring, whose first line is the summary that firna --help shows.

A stage is a step that reads input files and writes one output file, and it returns the path of that output. The stage contract states how a stage treats its output. The other steps do their work for each family or sequence and write into the family folders or into a run folder. Examples are build-alignments, evaluate-consensus and predict.

The work that a step does in worker processes is in firna.jobs, so a method holds only its options, its checks and the order of its work.

Keywords#

  1. Each keyword has a type and a help sentence. The permitted types are str, int, float, bool, Path and a list of these.

  2. A keyword that is None takes the default given by the layout or by the dataset config. A keyword has a value of its own only if its default is a constant.

  3. A keyword that holds several values has a plural name, for example families. The main output of a step is the keyword out. A keyword that names an input file is named for the file, for example cm, rfam_seed or hits_table.

  4. The names data_dir, overwrite and dry_run are reserved. The data folder belongs to the pipeline class. overwrite and dry_run are plain arguments of a stage, which are not made with option().

  5. A keyword of type bool defaults to True or False, never to None.

  6. A value given from Python is converted as a command line would convert it. A str given for a Path becomes a Path, and an int given for a float becomes a float. A value outside the choices of an option is refused.

  7. A step raises UsageError, a subclass of ValueError, for values that do not make sense together.

The settings of the dataset are saved in dataset/dataset-config.json. The name of a nested setting joins the names of its parents with two underscores, as in scikit-learn.

builder.config.set_params(stages__pretrain__ratios='90:5:5', filters__max_length=1000)

Input and output#

  1. Every default path comes from the layout of the data folder. A path given as a keyword replaces the default. A step does not construct a path of its own.

  2. A table is tab-separated text, optionally compressed with gzip, that pandas reads directly. The dataset is written as parquet. Records, settings and manifests are JSON. Sequences are FASTA and alignments are Stockholm.

  3. A file is written under a temporary name and renamed when it is complete.

  4. A stage saves the inputs and options of its output in <output>.run.json, and refuses to replace the output if the record no longer matches, unless it is given overwrite.

  5. A method that reads data returns a DataFrame, as DatasetBuilder.rows does.

  6. Progress is reported through the firna logger, which writes to standard error. Results that other programs read, such as a list of families, are written to standard output.

Package layout#

Dependencies run from the top of this table to the bottom. A layer imports only from the layers below it.

Layer

Modules

Contents

Interfaces

firna.cli

The commands, which are generated from the steps, and the few written by hand.

Pipeline classes

firna.pipelines

StructureBuilder, DatasetBuilder and ConsensusBenchmark, with one method for each step.

Work

firna.jobs

The work of the steps, including the per-family functions that run in worker processes.

Adapters

firna.io, firna.rfam, firna.downloads, firna.tools

File formats, Rfam’s files, fetching data, and the programs Infernal, Easel, R-scape and RNAfold.

Domain

firna.structures, firna.graph, firna.dataset

Algorithms that neither print nor read files.

Foundation

firna.errors, firna.layout, firna.stages, firna.logs

The two errors, paths, the stage contract and logging.
